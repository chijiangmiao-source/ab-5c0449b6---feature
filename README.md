# 星间中继网络演练台

链路切换后的路由复核工具：值班员录入路由器、有向邻接（含本地偏好与链路纪元）
与事件脚本（通告 / 撤销 / 断开 / 重连 / 投递），系统在后台逐步计算并保存检查点，
页面可逐步查看每台路由器的邻居入站路由、当前最优路径与待投递消息，并明确展示
**过期消息忽略**、**环路拒绝** 与 **恢复回放与不中断回放一致** 的收敛结论。

值班员还可在“待投递消息”表中选中任意消息，复核其**逐跳追溯**：每次实际尝试
列出发送与接收路由器、采用的前缀与最优路径、发送纪元、该跳裁决结果及未继续
转发的直接原因；链路断开重连或最优路径改变后的再次尝试按发生步骤追加，旧尝试
保持原样。

纯 Python 标准库实现，零第三方依赖。

## 快速开始

```bash
# 启动站点（宿主端口默认 8080，可用 HOST_PORT 配置）
docker compose up app
HOST_PORT=9000 docker compose up app

# 运行验收（代码测试 + 页面构建检查 + HTTP 冒烟，以退出码报告结果）
docker compose up --exit-code-from verify verify
# 或
docker compose run --rm verify
```

本地运行（无需 Docker）：

```bash
python3 scripts/build_page.py                 # 页面构建
PORT=8000 python3 -m app.main                 # 启动站点
APP_PORT=8000 python3 -m verify               # 另开终端运行验收
```

- 站点：`http://localhost:${HOST_PORT:-8080}/`
- 健康检查：`GET /healthz` → `{"status":"ok"}`

## 录入 DSL

**路由器**：空白分隔标识符，至多 8 台，如 `A B C D`。

**有向邻接**（每行一条）：`<源> <宿> pref=<本地偏好> [epoch=<起始纪元>]`

```
A B pref=100          # 等价于 A -> B pref=100 epoch=1
D A pref=50 epoch=1
```

**事件**（每行一项，至多 64 项）：

```
announce <从> <到> prefix=<前缀> [path=A,B,C] [epoch=N]   # 从==到 表示本机始发
withdraw <从> <到> prefix=<前缀> [epoch=N]
disconnect <从> <到>
reconnect  <从> <到>
deliver    <源> <宿> [msg=任意文本]
```

`#` 开头为注释。页面内置示例演练，覆盖全部规则场景。

## 语义规则

- **邻接方向**：邻接 `X->Y` 表示 X 向 Y 发送路由通告，Y 按该邻接的本地偏好
  评估来自 X 的入站路由；数据沿通告反方向转发（Y 的最优下一跳为 X 时，
  数据经邻接 `X->Y` 交给 X）。
- **链路纪元**：断开重连后纪元 +1。携带旧纪元的通告 / 撤销一律忽略；
  重连后发送方按新纪元向对端重发其全部已通告路由。
- **断开隔离**：邻接断开时，接收方立即清除来自该邻居的全部入站路由，
  已断开邻居不再参与任何路由器的选路。
- **撤销范围**：撤销仅移除该邻居、同一前缀、同一纪元的对应通告，
  不影响其他邻居或其他前缀的路由。
- **环路拒绝**：路径含接收路由器标识（或含重复路由器）的通告被拒绝；
  传播时若下一跳已在路径中，则不向该邻居传播。
- **最优路径**：按 本地偏好（高优先）→ 路径长度（短优先）→ 下一跳标识
  （字典序小优先）稳定裁决。
- **消息投递**：消息入队时快照全部邻接纪元；逐跳沿当前最优路径转发，
  每跳核验接收端邻接仍处于其发送纪元，否则消息按 **过期消息忽略** 处理；
  无可用路由时滞留为待投递，后续每个事件步骤自动重试。

## 消息逐跳追溯

- 消息首次入队后即保留稳定追溯记录（`trace`）：每次实际尝试记录发生步骤号，
  并逐跳列出发送与接收路由器、采用的前缀与最优路径、本地偏好、发送纪元
  （入队快照）与邻接当前纪元、该跳裁决结果及未继续转发的直接原因。
- 链路断开重连或最优路径改变后再次尝试时，旧尝试保持原样，新尝试按发生
  步骤追加；同一事件步骤内的自动重试不生成重复记录。
- 追溯记录随状态写入检查点：页面重开或后台从检查点恢复后，已完成与待投递
  消息的追溯顺序、内容及最终结果与不中断执行一致（由收敛校验覆盖）。
- 页面在“待投递消息”表点击「追溯」即可查看；亦可通过
  `GET /api/drills/current/messages/<编号>/trace` 查询当前演练中指定消息的
  完整追溯。不存在的消息或不属于当前演练的标识返回 `404` 及明确错误，
  不泄露其他演练的记录。

## 后台计算、检查点与恢复

- 演练创建后在后台线程逐项应用事件（默认每步 0.25s，可用 `STEP_DELAY` 调整），
  每完成一步即将检查点（事件、日志、完整状态、最优路径表）写入
  `${DATA_DIR}/runs/<序号>-<run_id>/steps/`。
- 页面重开（或服务重启）后自动恢复最后完整步骤；未完成的演练从断点继续执行。
- 新演练创建后，旧演练后台线程的迟到结果一律丢弃，不得覆盖新演练。
- 演练完成时自动从头不中断回放全部事件，并与检查点逐步比对，
  页面展示“恢复回放与不中断回放一致 ✓”的收敛结论。

## 验收服务（verify）

`verify` 容器执行以下验收并以退出码报告结果（0 通过 / 1 失败）：

1. **代码测试**：围绕旧纪元撤销、环路拒绝、恢复收敛等场景的 42 项单元 /
   集成测试（`tests/`），另含断开隔离、撤销范围、选路裁决、消息纪元核验、
   消息逐跳追溯、检查点恢复、迟到结果隔离等。
2. **页面构建检查**：核对 `build-manifest.json` 中页面产物的 SHA-256。
3. **HTTP 冒烟**：`GET /healthz`、站点首页与静态资源；并通过 API 端到端
   创建示例演练，等待后台计算完成，校验收敛一致及环路拒绝 / 旧纪元撤销 /
   过期消息忽略等关键日志均已展示。

## 项目结构

```
app/
  engine.py    # 路径矢量路由引擎（纯确定性状态机）
  drill.py     # DSL 解析与录入校验（8 台路由器 / 64 项事件上限）
  runner.py    # 后台计算、检查点持久化、断点恢复、收敛校验
  main.py      # HTTP 服务（/healthz、静态页面、演练 API）
  sample.py    # 预置示例演练
  static/      # 页面（index.html / app.js / style.css）
scripts/build_page.py   # 页面构建（生成 build-manifest.json）
tests/                  # 单元与集成测试
verify/                 # 验收服务（python -m verify）
Dockerfile / docker-compose.yml
```

## 环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `HOST_PORT` | `8080` | 宿主访问端口（compose） |
| `PORT` | `8000` | 容器内服务端口 |
| `DATA_DIR` | `/data` | 检查点数据目录 |
| `STEP_DELAY` | `0.25` | 后台每步计算间隔（秒） |
| `APP_HOST` / `APP_PORT` | `127.0.0.1` / `8000` | verify 目标地址 |
